# 59 — User-facing changelog

Builds out docs/55 D200 ("website changelog is hand-curated, not
generated from commits") into an actual pipeline. Discussed 2026-10-08.

## The problem

D200 settled what the changelog is (written for users, by hand, not a
commit dump) but nothing existed: no file, no page, no place in the app.
And a hand-written changelog with no structure tends to get skipped at
release time.

## The design

**One source: `app/CHANGELOG.md`** (D223). Plain Markdown, one `## `
section per app release, newest first. The next release's notes go under
`## Unreleased`; nobody has to guess the next version number while
writing. Format, kept deliberately small so one parser serves every
output:

```markdown
## Unreleased

An optional short paragraph.

- **Bold lead-in**: a bullet. **Bold** is the only inline formatting.
  An indented line continues the bullet above.
```

A malformed `## ` heading throws instead of silently merging two
releases. A test parses the real file, so CI catches it.

**One parser: `app/src/lib/changelog.ts`.** It has no imports and uses
only erasable TypeScript, so the app bundles it and Node 22+/24 runs it
directly from `scripts/build-changelog.mts`
(`node --experimental-strip-types`), with no build step or extra
dependency.

**Three outputs from the same text** (D224):

- **The website:** `website/changelog.html`, generated by
  `npm run changelog` and committed. Neither server needs a build step to
  serve it. It uses the current site's colour tokens and fonts, and gets
  restyled with the website refresh.
- **The app:** About → "What's new" shows the 3 newest released entries
  (bundled via `?raw`). Dev builds also show the `Unreleased` notes,
  marked "dev preview", so you can see how they read before releasing.
- **The stores:** `deploy-app.sh` prints the released entry as plain text
  (bold stripped, `•` bullets) for App Store "What's New" and Play Store
  release notes.

**Release integration** (D225). `scripts/deploy-app.sh`:

1. refuses to run if `## Unreleased` is missing or empty, unless
   `--no-changelog` is passed (for a fix nobody would notice);
2. after the version bump, turns `## Unreleased` into
   `## <version> — <today>` and regenerates the page;
3. commits both with the bump, under the same `app-vX.Y.Z` tag.

CI runs `npm run changelog -- --check`, which fails if the committed page
doesn't match the source (someone edited `CHANGELOG.md` without
regenerating).

**English only for now** (D226). The UI has no translation system yet
(docs/09 isn't built), so the changelog follows docs/51 D190's
English-only exception. A pt-BR pass belongs with the rest of docs/09.

**Only the app is versioned here.** api, database and PowerSync changes
get an entry only when users would notice them (D200), written as part
of the next app release's notes.

## Decisions locked in this doc

| # | Decision | Why |
|---|---|---|
| D223 | `app/CHANGELOG.md` is the single source, with notes written under `## Unreleased` | One place to write; no guessing the version number ahead of the release |
| D224 | The same entries feed the website page, About → "What's new", and the store release notes | Write once; the three can't drift apart |
| D225 | `deploy-app.sh` refuses to release without notes (unless `--no-changelog`), and stamps and commits them with the bump | Makes the changelog part of releasing instead of a step that gets skipped |
| D226 | English only until docs/09's translations exist | There's no translation system to hang pt-BR notes on yet |

## What's implemented

All of the above, 2026-10-08, with a first `## Unreleased` entry
summarising the app so far, which the user still needs to review. Verified:

- 11 parser tests (plus the full app suite, 109/109), `tsc -b`, oxlint.
- `npm run changelog`, `--check` and `--has-unreleased` on the real file.
- `deploy-app.sh` end to end in a throwaway clone with a local bare
  "origin": a `minor` release stamped `## 0.3.0 — <date>`, regenerated the
  page (one entry), committed both with the bump, tagged, pushed and
  printed the store notes; a second run with no notes refused and left
  the tree clean; `--no-changelog` released a plain bump.
- The dev server compiles About and the `?raw` import.

Not verified: how About and the page actually look. A headless browser
couldn't start in this sandbox (missing system libraries), so check
`app-beta.codexbase.dev/about` and `website/changelog.html` by eye.
